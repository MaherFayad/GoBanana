# GoBanana asset kit

Give a developer everything to build one wild page in the direction's style: override tokens, a Tailwind theme for that page, safe gradients, a font pairing and an icon set. The server returns text; you write the files.

## Ground rules

- **Page scope.** The kit is for the direction's pages only. Tokens are overrides that sit on top of the project's design system; they never replace its tokens, theme or global CSS. Use scope `system` only when the user asks in so many words.

- **No images in the kit.** Never download, save or copy reference images. The kit holds code and links only. Sources are listed with links.
- **Ship colors only in code.** Use colors tagged `ship` (WCAG 2.2: SC 1.4.3 at 4.5:1 for text, SC 1.4.11 at 3:1 for UI parts). `explore` colors may appear in comments as "concept only", never as tokens a developer would reach for.
- **Open licences only** for fonts (SIL Open Font License or Apache) and icons (Lucide: ISC, Phosphor: MIT).
- **File names in English, numbered in reading order**: left to right, then top to bottom, as the kit reads on the canvas. Inside files, number named items (like gradients) the same way, by their swatch position on the canvas (top row first, left to right).
- Plain words, no em dashes.

## Steps

1. **Find the canvas and direction.** Use the `canvasId` from this conversation, or ask. Call `get_canvas` and pick the kept direction (`directionId`) and its `pages`.
2. **Make sure there is a palette.** If none, call `extract_palette` with `addSwatches: true` (see gobanana-palette). Keep its `contrast` list; you need it for gradients.
3. **Export.** Call `export_kit` with `canvasId`, `directionId`, `pages`, `scope: "page"` and `formats: ["tokens", "tailwind"]`. The tokens come back as overrides for those pages.
4. **Write the kit** to `design/explorations/<slug>/kit/`, next to the direction's other files (or where the user asks). Use the folder from the returned `path`. Keep each returned file's extension, and add the number prefix:

   | File | What goes in it |
   | --- | --- |
   | `00-readme.md` | What the kit is, the pages it covers, that it inherits the project's system, the file list, and "ship vs explore" in two lines |
   | `01-tokens.json` | The `tokens` export, as returned |
   | `02-tailwind-theme.<ext>` | The `tailwind` export, as returned (CSS `@theme` or JSON) |
   | `03-gradients.css` | Gradients you build in step 5 |
   | `04-fonts.css` | The font pairing from step 6 |
   | `05-icons.md` | The icon set pick from step 7 |
   | `06-sources.md` | Every reference on the canvas as `[title](sourceUrl) (site)` |

   If the kit folder exists, ask before overwriting. Never edit the project's own `tailwind.config`, global CSS or token files; tell the user how to import the page theme on the scoped pages only.
5. **Gradients (max 4).** Build them only from the palette's `contrast` pairs tagged `ship`:
   - Take a passing pair (text color on background color). Find a second background color that also passes with the same text color. The gradient runs between the two backgrounds, so the text stays readable across the whole area.
   - For decorative areas with no text, both stops must still pass 3:1 against any UI part drawn on top.
   - Write each as a class and a custom property, with a solid fallback and the ratios in a comment:

     ```css
     /* 01 surface to secondary. on-surface text passes on both stops (7.2:1 and 5.1:1). */
     :root { --gradient-01: linear-gradient(135deg, #f4f1ea, #e8d9c4); }
     .gradient-01 {
       background-color: #e8d9c4;
       background-image: var(--gradient-01);
       background-image: linear-gradient(in oklch 135deg, #f4f1ea, #e8d9c4);
     }
     ```

     Use the stop with the lower ratio as the solid fallback.
   - If no pair qualifies, write the file with a comment saying so, and say it in your reply.
6. **One font pairing.** If the scoped DESIGN.md exists, use its `typography` fonts. If the export names a pairing (from the direction's card, else its `spec.typeVoice`), use that. **Card fonts:** a direction from the Banana Atlas exports its lead card's four families (Latin display and body, Arabic display and body); use all four exactly as exported, even when they are not in the table below (the Atlas checks every family against Google Fonts), and put the Arabic pair in `04-fonts.css` as `--font-display-ar` and `--font-body-ar` for `:lang(ar)`; each direction on a board gets its own pairing, so never copy one direction's fonts into another's kit. Otherwise pick one that fits the board's direction from GoBanana's curated list (all SIL Open Font License 1.1, on Google Fonts; the default is `space-grotesk-inter`). If the product is bilingual Arabic and English, pick a pairing with the `arabic` script.

   In `04-fonts.css`: a comment with the names, licence and Google Fonts links, `--font-display` and `--font-body` custom properties with sensible fallbacks, and a note that the team can self-host the files (for example with `@fontsource`) instead of loading from Google.

Keep both as exported: write the radii as `--radius-sm`, `--radius-md` and `--radius-lg` in `02-tailwind-theme`, never round corners a `none` card keeps square, and give every animation the reduced motion fallback (WCAG 2.2 SC 2.3.3).
7. **One icon set.** Pick one and say why in `05-icons.md`, matched to radius and stroke (with a card: `none` and `small` radius take Phosphor regular or Lucide at 1.5, `soft` takes Lucide, `round` takes Lucide or Phosphor fill):
   - **Lucide** (ISC): one consistent stroke on a 24 px grid, round caps. Pick it when corners are rounded (8 px or more) and the UI is calm. Set `strokeWidth` to match the body font: about 1.5 for light, 2 for regular, 2.5 for semibold.
   - **Phosphor** (MIT): six weights (thin, light, regular, bold, fill, duotone). Pick it for sharp corners, very thin or very heavy type, or wild directions that need fill or duotone.
   Include the install command (`npm i lucide-react` or `npm i @phosphor-icons/react`) and the chosen size, stroke or weight.
8. **Report** the folder, the file list, how many gradients passed, the font pairing and the icon pick. If the client cannot show the inline canvas, add the canvas web link.

## When things go wrong

- **Plan message** (`tokens` and `tailwind` are Pro formats): show it as is, with its upgrade link, once. Do not retry or loop. Offer what is free: DESIGN.md, DIRECTION.md and BUILD-PROMPT.md for the page (gobanana-design-md, gobanana-handoff). Gradients, fonts and icons can still be written from the palette if the user wants them.
- **Quota message:** same, relay once and stop.
- **Tool error or timeout:** retry once at most, then tell the user in one line.
- **GoBanana tools missing:** ask the user to enable the GoBanana connector (or run `/mcp` in Claude Code and log in).
