# Decisions

Deviations from `docs/banana-build-spec.md` and library choices, newest last.

| Date | Area | Decision | Why |
| --- | --- | --- | --- |
| 2026-10-11 | Repo | One GitHub repo (`GoBanana`) with `banana-server/` and `banana-plugin/` folders instead of two repos. | Owner started in a single repo. Folders match the spec names so they can split out later without moves inside each folder. |
| 2026-10-11 | MCP | `mcp-handler` 2.x renamed `createMcpHandler` to `createMcpRouteHandler` and now builds on `@modelcontextprotocol/server` 2.x (split SDK). Spec example uses the 1.x names. | Follow current library docs (spec rule 4). |
| 2026-10-11 | Tooling | TypeScript pinned to 5.9.3, not 7.x. | Next.js 16 type plugin and many tools still target the 5.x compiler API. |
| 2026-10-11 | Milestones | M1 infra code is written, but its "Done when" (live deploy + AuthKit login) needs owner credentials. Pure library work from M2 to M4 (bend engine, sources, layout, palette math, exports) was built in parallel because it has no dependency on M1 infra. | Unblocks progress while credentials are pending. Nothing is wired to production until M1 is verified. |
| 2026-10-11 | Sources | `web_search` image host rule: if Serper's `imageUrl` host is not allowlisted but its `thumbnailUrl` host is (Google thumbnails), keep the result and use the thumbnail URL as both image and thumb. If only the image host is allowlisted, the image URL is used as the thumb too. Drop only when neither host is allowlisted. | Spec section 8 says drop when the image host is not allowlisted. Pinterest pins often point at the original blog image, which would drop most results. Every URL we return is still on the allowlist, so the inline canvas CSP holds. |
| 2026-10-11 | Sources | `SourceQuery` gained an optional `sources` field, and the web_search adapter exposes `run()` returning `{ references, note, ok }` next to the spec's `search()`. | Spec signature has no way to pass selected sites or the "fewer results with a note" message. `ok` lets the tool count quota only when Serper answered. |
| 2026-10-11 | Sources | Results whose source page is not on a selected site are dropped; caller-typed `site:` operators are stripped from queries. Serper `num` is 2x count rounded up to 10, capped at 50. Takedown list load failure fails closed (no results, plain note). | Keeps results to the chosen sites and the Serper bill bounded; never shows results we could not check. |
| 2026-10-11 | Quota | Searches are counted only when Serper answers 200. Paid plans at the search cap get a reset date message, not an upgrade link. Item cap is all or nothing per `add_to_canvas` batch. | Users should not pay quota for our outages; paid users have nothing to upgrade to. |
| 2026-10-11 | Palette | Decoders: `jpeg-js` (typed-array mode, no Node `Buffer`) and `upng-js` (with `pako`), both pure JS, in memory. Quantizer: own deterministic median cut over a fixed sampling grid (20k samples total, alpha < 128 skipped), then merge clusters closer than 0.06 in OKLab and drop clusters under 1% of samples. `node-vibrant` not used. | Spec section 4 asks to record the choice. Pure JS runs on Workers without wasm setup; the merge and noise floor stop JPEG noise and edge blends from becoming fake swatches. |
| 2026-10-11 | Palette | WebP (and GIF) return `unsupported_format` and are listed in `skipped`. Recommended later: `@jsquash/webp` (libwebp in wasm, ESM, documented for Cloudflare Workers by importing the `.wasm` module and passing it to `init()`). Not installed. | Keeps v1 dependency free of wasm bundling; WebP thumbnails are skipped with a plain note instead of failing the call. |
| 2026-10-11 | Palette | `extractPalette` returns up to `size` colors, fewer when the images hold fewer distinct colors (no made-up tints). Roles are filled in order surface, on-surface, primary, accent, neutral, secondary; extras (size 7 to 9) get `neutral` or `secondary`. Output adds `skipped: [{ index, format, reason }]`. OKLCH strings use 3, 3 and 1 decimals; hex stays the source of truth. | Spec does not say what to do for flat images or sizes other than 6; inventing colors would misreport the references. |
| 2026-10-11 | Palette | `fetchThumbIntoMemory(url, { allowedHosts, fetchImpl?, maxBytes = 2 MB, timeoutMs = 8 s })`: https only, allowlist checked on every redirect hop (max 3, `redirect: "manual"`), image content type required, returns a result object and never throws or logs. | Spec gives no signature; a redirect must not escape the allowlist. |
| 2026-10-11 | Layout | Layout coordinates are absolute. by_direction: section frames have a 48 px title band and 16 px bottom padding; items with no known section go in a last column with no frame. grid: square cells, up to 4 per row. hero: first item is a 2x2 cell block (2 cells plus a gap), the rest in rows of up to 4 cells centered below it. Cell and column size default 280 px, gap 16 px for all layouts. | Spec section 9 gives only one line per layout; "ring below" read as centered rows under the hero. |
| 2026-10-11 | MCP | Correction to the row above: `mcp-handler` 2.3 still exports `createMcpHandler` (it is `createMcpRouteHandler` internally, re-exported under the old name). Options are one object: `createMcpHandler(init, { serverInfo, ...serverOptions })`. Tools use `server.registerTool(name, { inputSchema: z.object(...) }, (args, ctx) => ...)`; auth reaches tools as `ctx.http?.authInfo`. Endpoint wiring lives in `app/api/[transport]/handler.ts` so tests can build it; Next rejects extra exports from `route.ts`. | Checked against `node_modules/mcp-handler/dist/index.d.mts` and the SDK v2 types. |
| 2026-10-11 | Auth | AuthKit access tokens carry `sub`, `client_id`, `scope`, `org_id` and `sid`, but no `email`. On first sight the verifier upserts `users` by `workos_id` and fetches the email once from `GET https://api.workos.com/user_management/users/{sub}` (needs `WORKOS_API_KEY`). `users.email` is nullable in case that lookup fails, and a later request fills it in. Rows are cached per isolate for 5 minutes, so quota code must read `plan` from the DB, not from `authInfo`. | Spec says ping returns the user's email but tokens do not contain it (WorkOS token claims docs). |
| 2026-10-11 | Auth | Protected resource metadata uses `resource = MCP_RESOURCE_URL` (the `/api/mcp` URL), not the bare origin, so it matches the token audience. It is also served at `/.well-known/oauth-protected-resource/api/mcp`. Tokens must be RS256; issuer and audience are compared with or without a trailing slash. A bad token gives 401 with `WWW-Authenticate` and logs only the jose error code. | RFC 9728 path-suffixed lookup. Claude Code checks that `resource` matches the URL it connected to. |
| 2026-10-11 | Hosting | `next.config.ts` lists `@modelcontextprotocol/server` and `mcp-handler` in `serverExternalPackages`. | When Next bundles them it resolves the SDK `_shims` with Node conditions, which picks the Ajv validator. Ajv uses `new Function`, so every MCP and metadata route crashed on workerd with "Error compiling schema". Left external, OpenNext's esbuild picks the `workerd` shim (`@cfworker/json-schema`). Verified with `wrangler dev`. |
| 2026-10-11 | Hosting | **Needs lead action:** Next 16.4.0 does not run on `@opennextjs/cloudflare` 1.20.10 (latest). Every dynamic route throws `Unexpected loadManifest(/.next/server/preview-props.json)`, because OpenNext only inlines `*-manifest`, `required-server-files` and `prefetch-hints` JSON. This is the same class of bug as the `prefetch-hints` one fixed in 1.17.3. With `next@16.3.8` and `eslint-config-next@16.3.8`, the OpenNext build and the `wrangler dev` smoke test pass. Recommend pinning 16.3.8 until OpenNext ships a fix. | Next 16.4.0 was released 2026-10-06. |
| 2026-10-11 | Hosting | OpenNext caches stay at the defaults ("dummy"), with no incremental-cache R2 bucket, no `WORKER_SELF_REFERENCE` and no `IMAGES` binding. `images.unoptimized = true`. Compatibility date is 2026-10-01, because workerd 1.20261006 rejects later dates. Non-secret config goes in `wrangler.jsonc` `vars` and secrets go in `.dev.vars` or `wrangler secret put`. `cloudflare-env.d.ts` is generated by `wrangler types --strict-vars=false`. | All routes are dynamic. The Next image optimizer would proxy and cache third-party image bytes, which breaks hard rule 2. Strict vars would type `process.env` values as placeholder literals. |
| 2026-10-11 | Tooling | Added dev deps `eslint@^9` and `eslint-config-next` (flat config in `eslint.config.mjs`). | `npm run lint` had no ESLint installed. Next 16 removed `next lint`. ESLint 10 risks peer conflicts with `eslint-plugin-react`. |
| 2026-10-11 | Exports | `tokens` and `tailwind` are generated in-process (`lib/export/tokens.ts`, `tailwind.ts`), not by spawning the design.md CLI. They mirror `design.md export --format dtcg` and `--format css-tailwind` (v0.4.0) exactly; `tests/export-cli.test.ts` runs the CLI on every fixture and fails on any difference. Ours add only `$extensions.sources` (tokens) and a source-link comment above `@theme` (theme.css). | Workers cannot spawn a CLI. The package's library entry (`@google/design.md/linter`) reads `spec-config.yaml` from disk with `node:fs` at import time and pulls `node:module`/`tty`, so it cannot load in a Worker bundle; it is also only a devDependency. |
| 2026-10-11 | Exports | DESIGN.md color tokens are written as lowercase sRGB hex, not `oklch()`. The OKLCH value is kept in the Colors prose. | design.md 0.4.0 accepts `oklch()`, but its spec recommends hex, its exports convert everything to sRGB hex anyway, and hex keeps our in-process tokens identical to the CLI without a second color converter. |
| 2026-10-11 | Exports | Typography `lineHeight` is written as a quoted string (`"1.5"`). | design.md 0.4.0 silently drops a bare YAML number for lineHeight in `export` (only strings are parsed); a quoted unitless value lints clean and exports as `--leading-*` and DTCG `lineHeight`. |
| 2026-10-11 | Exports | DESIGN.md adds a `## Sources` section after Do's and Don'ts (lint accepts unknown sections). Front matter colors: ship palette colors and ship swatches, plus pure text colors (for example white) that appear in a ship contrast pair but not on the board. If no color has role `primary`, the first ship color that is not a surface or text role is named `primary` (lint warns otherwise). Components are generated so every ship color is referenced and every text pair reaches 4.5:1; a color with no 4.5:1 partner becomes a `fill-*` component with no text color. Rounded and spacing use a fixed starting scale. Typography uses four tokens (display, headline, body, label) from the chosen pairing; Arabic pairings get no letter spacing and taller line heights. | Spec template only shows the shape. Generated files must lint with zero errors and zero warnings, and the prose must explain where each value came from. |
| 2026-10-11 | Exports | Palette colors may have no `tag` (extract_palette tags contrast pairs, not colors). Exports then treat a color as ship when it is in a ship contrast pair. A swatch on the canvas with the same hex overrides the palette (the user's toggle wins). | Keeps the ship rule tied to WCAG results while respecting what the user set on the board. |
| 2026-10-11 | Exports | `CanvasSnapshot` (`lib/canvas/types.ts`) uses absolute canvas coordinates and adds optional `webUrl`. Items without `sectionId` are placed in a section by their center point. FigJam spec items are relative to their section (like Figma section children); items outside any section go in an "Unsorted" section; `sourceUrl` is on every item (the reference link, the board link for notes and swatches, the font link for type samples, or null when a stored link is not a safe http(s) URL). Unsafe source links (for example `javascript:`) are never emitted as links in any format; they are shown as plain text. | Spec section 10 gives the JSON shape but not the coordinate frame or what non-reference items link to. |
| 2026-10-11 | Kit | `lib/kit/fonts.json` holds 18 pairings, all SIL OFL 1.1 from Google Fonts, 7 with Arabic support (IBM Plex Sans Arabic, Noto Kufi Arabic, Readex Pro, Cairo, Tajawal, Alexandria, Almarai, El Messiri, Noto Naskh Arabic, Reem Kufi). Shape: `{ default, pairings: [{ id, name, display: { family, weight, fallback }, body: {...}, licence, scripts, mood, sample, url }] }`. Default pairing: `space-grotesk-inter`. | Owner targets GCC markets. Weights in each css2 URL are ones the family actually ships, so the URLs load. |
| 2026-10-11 | Next.js | Pinned `next` and `eslint-config-next` to exactly 16.3.8. | On 16.4.0 the OpenNext 1.20.10 Worker throws `Unexpected loadManifest(/.next/server/preview-props.json)` on every request; 16.3.8 serves metadata, 401 challenge and pages under `wrangler dev`. Re-test on each OpenNext release before unpinning. |
| 2026-10-11 | Milestones | Owner waived milestone gating: build continues as if M1 is done. M1 "Done when" (live login + `ping`) still needs owner credentials and stays on the launch checklist. | Owner instruction. |
| 2026-10-11 | Billing | Paddle webhooks are verified with our own Web Crypto code (`lib/billing/paddle.ts`), not `@paddle/paddle-node-sdk`. Scheme per Paddle docs: header `Paddle-Signature: ts=<unix>;h1=<hex>` (more than one `h1` during secret rotation, any match passes), HMAC-SHA256 over `${ts}:${rawBody}` with the destination secret, hex digest, constant-time compare, 5 second timestamp tolerance (Paddle SDK default, checked both ways). | SDK 3.x has a `workerd` export, but Next bundles server code with Node conditions (see the `serverExternalPackages` row), so we would get the `node:crypto` build. We only need one HMAC and no Paddle API calls, so zero dependencies is simpler. |
| 2026-10-11 | Billing | Plan mapping: `transaction.completed` with `PADDLE_PRICE_FOUNDING` sets `founding` from any plan; `subscription.created`/`updated` with status active, trialing or past_due set `pro_monthly`/`pro_yearly` by price id, but only from free or Pro (never over founding); status canceled or paused and `subscription.canceled` set `free` only from Pro, so a founding buyer is never downgraded. `userId` comes from `custom_data.userId` and must be a uuid. Storage failures return 500 so Paddle retries; the stub repo throws in production for the same reason. | Spec says "set users.plan on purchase and subscription created, updated and canceled" without covering founding plus subscription overlap. |
| 2026-10-11 | Billing | Founding cap of 100 is enforced on the pricing page (no checkout once 100 users hold `founding`, and none while the count is unknown). A buyer who already paid always gets the plan, even past 100 (logged). Also set a 100 unit limit on the Paddle price or a discount if Paddle offers one. | Paddle has no built-in sales cap on a price that we rely on; racing buyers at 99 can reach 101. |
| 2026-10-11 | Site | Site routes are `app/(site)/[locale]/...` with `en` and `ar` (`/en`, `/ar/pricing`, ...), `dynamicParams = false`. `/` stays with `app/page.tsx`. Copy lives in `lib/site/dict/{en,ar}.ts` (Arabic typed against the English shape), legal drafts in `lib/site/legal/`. | Keeps one layout for both languages and avoids colliding with `/`. |
| 2026-10-11 | Site | `proxy.ts` (Next 16 name for middleware, Node runtime) adds `X-Robots-Tag: noindex` on `/s/*` and `/c/*` and sets request header `x-site-locale` on `/en/*` and `/ar/*` so the root layout can render `<html lang dir>`. OpenNext 1.20 bundles Node middleware. | App Router pages cannot set response headers; `next.config` `headers()` would also work for noindex. |
| 2026-10-11 | Canvas | `canvases.state` JSON is `{ version: 1, viewport, nodes, tray }` (`canvas/types.ts` `CanvasState`). Nodes are stored lean (`id, type, x, y, w, h, parentId?, z?, data`), child coordinates relative to their section. The tray (search results waiting to be placed) lives in the same JSON. | Spec section 11 says state holds "nodes + viewport"; the tray must survive reloads and show on web and inline alike, and one JSON blob keeps the two surfaces in sync without a second table read. |
| 2026-10-11 | Canvas | Keyboard moves use our own handler: arrows nudge the focused node 8 px (Shift 32 px) whether or not it is selected, `+`/`-` resize by 32 px, `M` (or Shift+F10) opens the node menu, `F2` edits, `Delete` removes. React Flow's built-in delete key is off. | React Flow 12 moves only selected nodes, by 5 px (x4 with Shift). The extra keys give resize and menu a keyboard path (SC 2.5.7). |
| 2026-10-11 | Canvas | Removing a section keeps its contents (they move to the top level at the same screen spot). Dropping or nudging a node so its center lands in a section puts it in that section; moving it out takes it out. | Deleting a frame should not silently delete references; matches the spec's "Move to section" menu semantics for drag. |
| 2026-10-11 | Canvas | `/c/:id` server loader is a stub (`canvas/server-stub.ts`) that returns `state: null`, so the client loads through `GET /api/canvas/:id` until `db/` is wired. Contract: GET returns `{ state }` already takedown filtered; PUT takes `{ state }`. | Another agent owns `db/` and the API route; the page works end to end against the API in the meantime (e2e mocks it). |
| 2026-10-11 | Data | Repositories live in `lib/db/` as ports (`lib/db/types.ts`) with a Drizzle version per table (each function takes the db first) and an in-memory version (`lib/db/memory.ts`) for tests. Tools and routes take `Repos`, never `db/`. `users.plan` is read from the database on every limited call (not from the per-isolate user cache). Ids that are not uuids short-circuit to "not found" without a query. | Lets every tool run in Vitest with no network or database, and keeps Postgres from erroring on bad uuid input. |
| 2026-10-11 | Data | `bend_brief` takes an optional `canvasId`. With it, the directions are upserted into `directions` keyed by a new nullable `bend_id` column (stable bend id, unique with `canvas_id`; migration `0001_directions_bend_id.sql`), and the canvas gets the bend's wildness and lens (and the brief when it had none). `search_references` resolves `directionId` as a row uuid or a bend id on any of the user's canvases (narrowed by `canvasId` when given). Without a saved direction the agent passes the direction's `searchQuery` as `query`. Section nodes and tray entries use the bend id as `directionId`. | Bend ids are seeded and cannot be reversed into a query. A column keeps the id the agent saw usable without a canvasId, and a bend is deterministic, so any matching row has the same query. Lead's preferred approach. |
| 2026-10-11 | Data | `search_references` without `canvasId` returns results without saving them. With a canvasId, results go to `references` with row id = uuid v5 of (canvasId, `ref_...` id), and to the canvas tray (newest first, max 200, deduped). `add_to_canvas` resolves a `referenceId` from `references` first, then from the tray. | `references.canvas_id` is NOT NULL. Search ids are stable (hash of source and image URL), so the same id can be saved later and found again by canvas. |
| 2026-10-11 | Quota | Canvas quota counts canvases the user owns (`canCreateCanvas`), and `usage.canvases` is also incremented per month for reporting. Two parallel creates at the limit can both pass. Usage increments are one `INSERT ... ON CONFLICT DO UPDATE` with `+ n`. The item cap counts every node on the canvas (sections, notes and swatches too), including sections that `add_to_canvas` creates for directions. Upgrade links point to `${APP_URL}/en/pricing`. | Spec section 12 says "Canvases: 3" (owned), not per month. The race only lets a user hold one extra canvas; a locking insert is not worth it on Neon HTTP. |
| 2026-10-11 | Canvas | The server stores the canvas UI's `CanvasState` as is and reuses `canvas/state.ts` (`parseState`, `filterBlocked`, `stateToItems`) and `canvas/layout-adapter.ts`, so `arrange_canvas` gives the same result as the toolbar. `lib/canvas/store.ts` adds: takedown filter on every load (fails closed when the list cannot load; a later tool write saves the filtered state), optimistic saves on `updated_at` with one retry for tool writes, and the mapping to `CanvasSnapshot` (sections split from items; directions use their bend id; wildness 3 when the canvas was never bent). | One parser means the inline canvas, the web canvas and the tools never disagree about what a valid node is. |
| 2026-10-11 | Canvas | `add_to_canvas` placement: new sections go in a row to the right of top-level content; items with a target section go in rows of 4 below that section's contents and the frame grows; other items go in rows of 4 below all top-level content. A reference whose tray entry has a saved direction goes to that direction's section, created on first use. Section items take an optional `directionId`. Placed references leave the tray, as when the user drags them in. Unknown or taken down references are skipped and listed; the rest of the batch still lands. | Spec says only "items: [{ id, x, y }]". Spec section 11 says a direction becomes a section. |
| 2026-10-11 | Canvas | `/api/canvas/:id`: GET returns `{ state, title, updatedAt, removed }`; PUT takes `{ state, baseUpdatedAt? }` (zod checked, 1 MB cap, max 2000 nodes, any `data:`, `blob:` or `filesystem:` string anywhere gives 400) and answers 409 when `baseUpdatedAt` is given and stale; without it the last write wins. 404 for both missing and not yours. Responses are `no-store` and `noindex`. | Hard rule 2 must hold even if a client tries to embed bytes. The optional base version lets the UI avoid overwriting tool changes once it sends it. |
| 2026-10-11 | Auth | **Needs lead action:** the canvas API accepts the AuthKit bearer token (same verifier as MCP) but the web session is not wired (TODO in `app/api/canvas/[id]/route.ts`), so `/c/:id` gets 401 from the API for now. `@workos-inc/authkit-nextjs` 4.4.0 supports Next 16 `proxy.ts`, but `withAuth()` only works behind its proxy (`authkit()` composed into `proxy.ts`, owned by the site work) plus an `/auth/callback` route with `handleAuth()` and `WORKOS_COOKIE_PASSWORD`; its README says nothing about Cloudflare Workers or OpenNext. Not installed. | 2026-10-11 | MCP | All tools advertise strict JSON schemas but validate inside the handler (`lenient()` in `lib/mcp/tools/types.ts`), so bad input gets a plain message.
